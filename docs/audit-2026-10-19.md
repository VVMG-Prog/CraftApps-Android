# Audit — 2026-10-19 (after the 0.4.0–0.4.3 fixes)

An audit of the CraftApps Android ports for the same class of bug the 0.4.x
fixes uncovered: **code that looks alive but never runs**, and **documentation
that promises patches which were never applied**.

The seed of the audit: the S Pen button "does not work" note in `AGENTS.md`
was based on a test that ran through a Java hook that never fires. If one
conclusion was wrong that way, others may be too.

---

## 1. Fixed in 0.4.2 / 0.4.3

| # | Finding | Fix |
|---|---|---|
| 1 | `crates/ui-egui/src/view_cmds.rs`: `hides_chrome()` had **no Android gate**, although `docs/android-upstream-patches.md` listed one. In the *fullScreen* screen mode the menu bar, the options bar, the status bar and the toolbar all disappear — on Android that removes the only route to *Edit ▸ Stylus Settings…* and *Help ▸ Check for Updates*. | The documented patch applied (`#[cfg(target_os = "android")] { false }`). |
| 2 | `xtask/src/layers.rs`: the port crate was **not in the layer table**, so the upstream's own `cargo xtask layers` check could not classify it. The patch was listed in the documentation but never applied. | `("android", Class::Exempt)` added. |
| 3 | `shared/src/saf.rs`: ten dead items left by the JNI picker path (`ACTION_OPEN_DOCUMENT`, `ACTION_CREATE_DOCUMENT`, `CATEGORY_OPENABLE`, `EXTRA_MIME_TYPES`, `EXTRA_ALLOW_MULTIPLE`, `EXTRA_TITLE`, `add_category`, `put_extra_bool`, `put_extra_string`, `put_extra_mime_types`) — a warning on every build. | Removed. The shared crate now builds warning-free. |
| 4 | The **workspace-level `AGENTS.md` had drifted** from the repository's: it was a stale copy that still claimed "the S Pen button does not work". An agent starting in the workspace root would read the wrong thing. | The workspace file is now a **symlink** to `craftapps-android/AGENTS.md` — one source of truth. |
| 5 | `docs/android-upstream-patches.md` listed the `xtask/src/layers.rs` and `crates/ui-egui/src/view_cmds.rs` patches for **the other apps as well**, and none of those apps has either. | Listed in the TODO list of `AGENTS.md` (finding 2 above applies to all five). |
| 6 | The Stylus Settings had **no diagnostic for the stylus events** — the reason the old "the button does not work" conclusion was wrong is that nobody could see what the tablet sends. | The Stylus Settings now show the **hovering** state and the **last stylus event** (action, button bits, tool type). See `docs/README.md`. |

**Lesson:** a patch listed in the documentation but not applied is worse than
no patch — the next agent trusts the list. Cross-check the list against the
tree (and the tree against the list) whenever you touch either.

## 2. Found — the other four apps have the same bugs (not fixed)

PhotoCraft was the reference port, so the bugs that were fixed there are
still there in VectorCraft, LightCraft, DesignCraft and PdfCraft. All four
are listed in the "Known Issues & TODO" section of `AGENTS.md`; the detail:

| App | The picker bridge | The bridge response | `CRAFTAPPS_BRIDGE_DIR` | The stylus data | The modifiers |
|---|---|---|---|---|---|
| **VectorCraft** | `startPickerBridge()` **defined but never called** | never polled | not set | not fed | not tracked |
| **LightCraft** | **defined but never called** | never polled | not set | not fed | not tracked |
| **PdfCraft** | **defined but never called** | never polled | not set | not fed | not tracked |
| **DesignCraft** | started in `onCreate` ✓ | **never polled** | not set | not fed | not tracked |

What that means in practice, per app:

1. **The system file picker never opens** (VectorCraft, LightCraft, PdfCraft):
   Rust writes the request, but the Activity never polls for it.
2. **The file dialog hangs after picking a file** (all four): the reply is
   parked in the SAF pending slot (`saf::set_pending_open` /
   `set_pending_create`), which is only answered by `nativeOnActivityResult`
   — and the bridge's request codes (1001/1002) never reach it. The answer
   sits in `response.json` and nobody reads it.
3. **The bridge directory collides**: without `CRAFTAPPS_BRIDGE_DIR` the
   fallback is `/sdcard/CraftApps/.picker` — one directory shared by all five
   apps (a request written by one app can be picked up by another), and it
   needs "All files access" (the per-app directory does not).
4. **The S Pen's button, the eraser end and palm rejection do nothing** in
   them: nothing feeds the stylus data to the pen runtime, and their
   workspaces have no `[patch.crates-io] android-activity` entry.
5. **Every Ctrl/Shift/Alt shortcut is dead** in them: winit sends no
   `ModifiersChanged` and nothing tracks the modifier keys.
6. Their Java activities still carry the **dead input-forwarding code**
   (`dispatchTouchEvent`, `dispatchKeyEvent`, …) — harmless, but it reads as
   if it works.

The port of each fix is small: the shared crate already holds the code.

### How to check each finding on a tablet

| Finding | How to see it |
|---|---|
| The picker never opens | *File ▸ Open ▸ Browse other locations…* — nothing happens (VectorCraft, LightCraft, PdfCraft). |
| The dialog hangs after the pick | Pick a file in the system picker: the app stays busy / the dialog never closes (all four). |
| The bridge directory collides | Two apps open a picker at once, or "All files access" is off and the picker never starts. |
| The S Pen's button does nothing | The Stylus Settings' button dots never light up. |
| The eraser end does nothing | Flip the pen and draw: it paints instead of erasing. |
| Every Ctrl shortcut is dead | Ctrl+O / Ctrl+Z with a Bluetooth keyboard: nothing happens. |
| The chrome can disappear | *View ▸ Screen Mode ▸ fullScreen*: the menu bar and the options bar vanish (the `hides_chrome()` gate — fixed in PhotoCraft, still open in the others). |

## 3. Smaller observations

* **`shared/` builds on the host only for `cargo test`.** The `x11`
  dev-dependency (needed because winit refuses to compile without a window
  system) is unified into the build only for the test target, so a plain
  `cargo check` in `shared/` fails with *"The platform you're compiling for
  is not supported by winit"*. Use `cargo test` there; the Android build is
  unaffected.
* **`saf::launch_open_document_tree` is still the JNI path** (used by
  LightCraft and PdfCraft). It launches the picker from the render thread,
  which is exactly the failure the file bridge was written for. PhotoCraft
  uses the bridge (`PickerKind::Folder`); the other two should too.
* The **Java pen side-channel** is dead everywhere (§ the input trap in
  `AGENTS.md`). It is kept deliberately — it is the only possible path to the
  barrel button if the app ever stops being a `NativeActivity` — but the
  comment in each activity must say so, or the next agent will trust it.
* The **`AGENTS.md` "Reference Repos"** entry for `2IIZ/spen_remote` says
  "DOESN'T WORK on S6 Lite". That is right for the *S Pen Remote SDK* (it
  needs a Bluetooth S Pen) but must not be read as "the button does not
  work" — it does.
* The other four apps' upstream trees have **no `("android", Class::Exempt)`
  entry** in `xtask/src/layers.rs` either — the same missing patch as
  PhotoCraft's (fixed there in 0.4.2/0.4.3).
* The **accesskit gate** the documentation lists for the other apps is not
  needed: every workspace already uses `eframe = { default-features = false }`,
  so `accesskit` is never enabled. The documented "check exact dep line" was
  the right hedge — but the note should say *why* it is unnecessary, or the
  next agent will re-check it every time.

## 4. How this audit was done (repeatable)

1. **Read the AOSP contract** for every platform API the port relies on
   (`takeInputQueue`, `InputQueue`, `MotionEvent`) instead of trusting the
   notes.
2. **Compare the documentation with the tree**: every patch listed in
   `docs/android-upstream-patches.md` must exist in the source, and every
   `#[cfg(target_os = "android")]` hunk in the source must be listed.
3. **Search for dead code paths**: a function that is defined but never
   called, a queue that is written but never read, a constant that is never
   used (the compiler says so — the build log had 11 warnings for months).
4. **Check the other apps** for the same patterns: the shared crate means a
   fix in one app is a fix in all of them, and a bug in one app is a bug in
   all of them.
5. **Check that the documentation has one source of truth** (the two
   `AGENTS.md` files had drifted).
